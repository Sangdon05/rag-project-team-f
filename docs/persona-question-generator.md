# 페르소나별 자연어 질문 생성기 예시

형태: LLM에 복사해 사용할 질문 생성 프롬프트와 가상 출력 예시.

목적은 사용자가 정확한 도감 용어를 몰라도 입력할 법한 질문을 모으는 것이다. 질문 생성과 정답·근거 검수는 분리한다. 생성한 문장은 실제 사용자 조사 결과가 아니며, 이 기획 문서는 서비스 검색 색인에 넣지 않는다.

이 문서는 **같은 정보 요구를 두 페르소나의 표현으로 만드는 통제 예시**다. 실제 여정에서는 서로 다른 개념·비교 질문이 나올 수 있으며, 이를 같은 정답으로 묶지 않는다. 상세 페르소나·공통/개별 여정·질문별 답변과 오답 기준은 [problem.md](problem.md)를 따른다.

## 1. 입력할 공통 상황

- 게임: 1세대 Red/Blue. 싱글 배틀을 준비하며 도감을 찾는다.
- 이번 가상 상황에서는 상대가 롱스톤이라고 미리 주어진다.
- 후보: 파이리·꼬부기·피카츄, 모두 레벨 20.
- 현재 기술: 파이리의 불꽃세례·할퀴기, 꼬부기의 물대포·몸통박치기, 피카츄의 전기쇼크·전광석화.
- 피카츄는 현재 10만볼트를 보유하지 않았다.
- 상태 이상·능력 변화 없이 기본 타입을 유지하며, 남은 PP는 충분하다.

이것은 기획용 보유 목록이다. 게임을 처음 시작하면 자동으로 주어지는 목록을 뜻하지 않는다. 실제 입력에 상황이 없으면 생성기가 임의로 채우지 않는다.

## 2. 페르소나와 정보 요구

| 대상 | 공통 배경 | 질문 표현의 설계 가설 |
| --- | --- | --- |
| P1: 초등 저학년 초보자 | 기초 메커니즘은 알지만 1세대 게임에서 적용하는 것은 처음 | 현재 선택·상성 비교·다음 행동을 직접 묻는 일상 표현 |
| P2: 성인 초보자 | 1세대 게임을 처음 접하며 기술·진화·상성의 기초가 낯섦 | 무엇을 확인해야 하는지 묻거나 선택 이유·준비 방법을 확인하는 일상 표현 |

말투·지식 수준은 추가로 설정할 수 있다. 성인이 전문 용어를 알거나 저학년이 항상 유아체를 쓴다고 가정하지 않는다. 같은 정보 요구의 대상·관계·조건은 유지한다.

| 정보 요구 ID | 확인하려는 정보 |
| --- | --- |
| I01 | 롱스톤이 어떤 포켓몬인지 기본 정보 확인 |
| I02 | 주어진 후보와 현재 기술로 롱스톤을 상대할 준비 선택 |
| I03 | 피카츄가 10만볼트를 배우는 방법 확인 |

## 3. 복사해 사용할 생성 프롬프트

~~~text
당신은 포켓몬 게임 초보자의 자연스러운 질문 후보를 만드는 기획 보조자다.

[공통 상황]
게임은 1세대 Red/Blue이며 싱글 배틀 전 도감을 찾아본다.
상대는 롱스톤으로 주어졌다.
후보는 레벨 20의 파이리·꼬부기·피카츄다.
현재 기술은 파이리: 불꽃세례·할퀴기,
꼬부기: 물대포·몸통박치기, 피카츄: 전기쇼크·전광석화다.
피카츄는 10만볼트를 보유하지 않았다.

[페르소나]
P1. 기초 메커니즘은 알지만 실제 1세대 게임에 적용하는 것은 처음인 초등 저학년생
P2. 스토리와 일부 캐릭터는 알지만 기술·진화·상성의 기초는 낯선 성인
두 사용자 모두 게임은 처음이다. 제시하지 않은 지식 수준을 나이로 추정하지 않는다.

[정보 요구]
I01: 롱스톤의 기본 정보가 궁금하다.
I02: 후보와 현재 기술 중 이번 상대에게 준비할 선택이 궁금하다.
I03: 피카츄의 10만볼트 습득 방법이 궁금하다.

[작성 규칙]
1. 각 페르소나별로 I01~I03 질문을 하나씩, 총 6개 작성한다.
2. 같은 ID의 질문은 대상·관계·조건·원하는 정보를 유지한다.
3. 일상 표현을 사용하되 나이에 따른 유아체·과장된 말투를 강제하지 않는다.
4. 공통 상황에 없는 보유 기술·상대·버전·취향·진행 상태를 만들지 않는다.
5. 정답·상성 배율·예상 수치·허용 근거는 입력받거나 출력하지 않는다.
6. 빠진 조건은 몰래 채우지 말고 '추가 확인'에 표시한다.
7. 자료로 답하기 어려운 질문도 억지로 검색 용어에 맞춰 고치지 않는다.
8. 표현만 다른 질문을 서로 다른 정보 요구라고 계산하지 않는다.

[출력]
표로 작성한다.
열: 페르소나 / 정보 요구 ID / 자연어 질문 / 사용한 상황 정보 / 추가 확인
답변 가능 여부·정답·출처의 확정은 이후 원문 검수 단계로 남긴다.
~~~

## 4. 가상 출력 예시

| 페르소나 | ID | 자연어 질문 | 사용한 상황 정보 | 추가 확인 |
| --- | --- | --- | --- | --- |
| 성인 | I01 | 롱스톤은 처음 보는 이름인데, 어떤 포켓몬인지 알려주세요. | 이름·버전 | 기본 정보 조회에는 추가 입력 불필요 |
| 초등 저학년 | I01 | 롱스톤이 뭐야? 어떤 포켓몬이야? | 동일 | 동일 |
| 성인 | I02 | 롱스톤을 상대할 때 제가 가진 세 마리 중 누구를 쓰면 좋을까요? 지금 가진 기술로 봐주세요. | 상대·후보·현재 기술 | 공통 상황이 함께 전달되면 재질문 불필요 |
| 초등 저학년 | I02 | 롱스톤이랑 싸울 건데 파이리, 꼬부기, 피카츄 중 누구 써? 지금 있는 기술로 알려줘. | 동일 | 동일 |
| 성인 | I03 | 피카츄에게 10만볼트가 없는데, 레벨을 더 올리면 배우나요? | 버전·포켓몬·기술·미보유 | 레벨업 습득을 전제로 하는지 원문으로 검증 |
| 초등 저학년 | I03 | 피카츄 10만볼트는 어떻게 배워? 레벨 올리면 돼? | 동일 | 동일 |

6개 표현이지만 공통 정보 요구는 3개다. 같은 사실의 표현 변형으로 공식 평가의 고유 문항 수를 늘리지 않는다.

### 맥락·자료 부족을 점검하는 추가 입력

| 입력 | 확인할 것 |
| --- | --- |
| 얘한테 뭘 써? | 현재 세션에서 얘가 누구인지 명확한가? 모호하면 대상만 확인 |
| 이 포켓몬 어디서 잡아? | 대상·버전이 있는가? 실제 획득 자료가 없다면 보강 대상으로 표시 |

## 5. 생성 뒤 팀이 할 검수

1. 같은 ID의 두 질문이 실제로 같은 대상·조건·정보를 요구하는지 확인한다.
2. 현재 자료로 답할 수 있는지, 사용자 입력이 필요한지, 원문 보강이 필요한지 구분한다.
3. 채택한 개발 질문에 필수 정답·원문 위치·허용 대안·오답 기준을 붙인다.
4. 자연어 질문을 정확한 검색어로 사용자에게 다시 쓰게 하지 말고, Agent가 이름·맥락·관계를 연결하는지 점검한다.
5. 고정한 최종 평가 문항을 성능에 맞춰 다시 생성·수정하지 않는다.

이 문서는 질문 생성 예시다. 서비스의 자동 생성 기능이나 사용자 학습 효과가 구현·검증됐다는 의미는 아니다. 프로젝트 범위와 성공 기준은 [problem.md](problem.md)를 따른다.
