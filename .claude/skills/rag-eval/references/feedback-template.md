# 평가셋 의견서 템플릿

파일: `eval/feedback/{YYYYMMDD}-{split}.md`. 평가셋은 고치지 않고 이 의견서만 쓴다. 반영 여부는 사용자가 정한다.

```markdown
# 평가셋 의견서 — {split} {label}

- 검토 대상: eval/{split}.json (sha256 앞 12자: ...)
- 잠금 확인: ok | 실패 (내용)
- 청크 기준: chunks.jsonl sha256 앞 12자, index_version

## 요약
- 차단 (평가 실행 불가): n건
- 권고: n건

## 의견
| # | qid | 종류 | 근거 | 제안 |
| --- | --- | --- | --- | --- |
| 1 | D03 | 근거 매핑 낡음 | allowed_evidence의 pokemon:35#stats가 현재 청크에 없음 | 매핑 갱신 후 재잠금 |
```

## 의견 종류

| 종류 | 차단 여부 | 예 |
| --- | --- | --- |
| 스키마 위반 | 차단 | 필수 필드 누락, qid 중복 |
| 근거 매핑 낡음 | 차단 | chunk_id가 현재 청크에 없음 |
| 잠금 불일치 | 차단 | `verify` 실패 |
| 문항 수·유형 분포 불일치 | 권고 | dev가 답변 가능 7 / 근거 없음 3 |
| 정답 오류 의심 | 권고 | key_facts가 `data/processed/` 값과 다름 |
| 질문 모호 | 권고 | 세대 기준이 없어 정답이 둘 |
| 혼동 쌍 부족 | 권고 | confusable 문항에 `confusable_with` 없음 |
| dev/test 중복 | 권고 | 거의 같은 질문이 양쪽에 있음 |
| 근거 없음 문항 검증 | 권고 | 실제로는 근거 청크가 있어 보임 |

정답이나 근거를 대신 써 넣지 않는다. 제안은 "무엇을 확인할지"까지만 쓴다.
