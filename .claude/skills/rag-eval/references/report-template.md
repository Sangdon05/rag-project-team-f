# 비교 보고서 템플릿

파일: `results/reports/{YYYYMMDD}-{name}.md`

```markdown
# {A vs B vs C | C vs C+RW} 비교

## 조건
- 평가셋: {label} ({sha256 앞 12자}), split {dev|test}, 문항 수
- run_id: A=..., B=..., C=..., C+RW=...
- 공통: 생성 모델, 프롬프트 버전, 출력 한도, 컨텍스트 수·길이, index_version
- 구성별 설정: (A) 임베딩·k / (B) 후보 수·RRF·중복 제거 / (C) reranker·입력 후보·출력 k / (RW) 리라이트 모델·프롬프트
- 다른 점이 있으면 여기에 명시 (없으면 "없음")

## 필수 지표
| 지표 | A | B | C | C+RW |
| --- | --- | --- | --- | --- |
| Hit@5 | x/17 | | | |
| 정답 충족 | x/17 | | | |
| 근거 적합 | x/17 | | | |
| 근거 없음 대응 | x/3 | | | |
| 호출 성공 | x/y | | | |
| 응답 시간 평균 / 중앙값 (n) | | | | |
| 오류 / timeout | | | | |

## 문항 단위 변화
- 개선된 문항: qid 목록 (이전 구성 대비)
- 나빠진 문항: qid 목록과 원인

## 실패 유형
| 유형 | A | B | C | C+RW |
대표 사례 (유형별 1~2건): 질문, 후보 순위, 인용, 답변 발췌, 판단

## 리라이트 검증 (C vs C+RW)
- 의도 변경 건수, fallback 건수, 추가 지연, 품질 악화 문항

## 트레이드오프
| 구성 | 품질 | 지연 | 호출 비용 | 운영 제약 |

## 한계
- 평가셋 20문항, 제한된 문서 범위의 결과임
- 사람 채점 불일치 건수와 해소 방법
- retry / extra run이 있으면 목록 (본 평가와 분리)
```

채택 권고를 쓰지 않는다. 판정은 오케스트레이터가 한다.
