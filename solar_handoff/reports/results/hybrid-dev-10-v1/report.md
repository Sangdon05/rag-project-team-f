# 개발 검색 비교: Vector 단독 A vs BM25 + Vector B

> **한눈에:** 답변 가능한 8개 질문의 잠정 지정 근거 기준으로, 세 모델 모두 A와 B의 Hit@5는 **8/8**이다. 지정 근거를 모두 찾은 complete@5는 Gemma가 **7/8 → 6/8**, KURE와 OpenAI는 각각 **8/8 → 8/8**이다. 작은 개발 표본의 검색 순위 관찰이며 답변 품질이나 전반적 우열을 뜻하지 않는다.

| 항목 | 내용 |
|---|---|
| 질문·코퍼스 | 영문 Red·Blue 개발 후보 10문항, 답변 가능 8·범위 밖/정보 부족 2; 151문서의 A안 1,504청크 |
| 실험 | 각 모델에서 A=Vector 단독, B=BM25와 해당 모델 Vector의 RRF 결합. 생성 없이 각 30건 검색, 모두 `ok`, 최종 5개씩 |
| 상태 | 잠정 개발 스모크 테스트, `scoring_pending`. 질문·지정 근거는 공식 확정이 아니며 사람의 답변·근거 채점 미실시 |
| 비교 조건 | 동일 DB·텍스트와 질문을 사용한 기록이지만 B 질의는 새 임베딩 요청이다. B 벡터 top5 ID 순서는 A와 모델별 0/10 변화; 벡터·거리의 비트 일치는 미증명 |

## 결과: 지정 근거 회수 (분모는 답변 가능 8문항)

각 칸은 **A → B**이다. `Hit@k`는 지정 청크 중 하나라도 상위 k에 있으면 적중, `complete@k`는 지정 청크가 전부 상위 k에 있어야 적중이다. 예를 들어 D05는 피카츄가 TM24를 배운다는 근거와 TM24 획득 장소·방법 근거가 각각 필요하다. 하나만 있으면 Hit에는 포함되지만 complete에는 포함되지 않는다. 단일 앵커 문항에서는 두 지표가 같다. D09·D10은 분모에서 뺀다.

| 모델 | Hit@1 | Hit@3 | Hit@5 | complete@1 | complete@3 | complete@5 |
|---|---:|---:|---:|---:|---:|---:|
| Gemma | 7/8 → 7/8 | 8/8 → 8/8 | 8/8 → 8/8 | 4/8 → 4/8 | 6/8 → 6/8 | **7/8 → 6/8** |
| KURE | 8/8 → 7/8 | 8/8 → 8/8 | 8/8 → 8/8 | 5/8 → 5/8 | 8/8 → 7/8 | 8/8 → 8/8 |
| OpenAI | 8/8 → 7/8 | 8/8 → 8/8 | 8/8 → 8/8 | 5/8 → 5/8 | 7/8 → 8/8 | 8/8 → 8/8 |

- **D05가 차이를 설명한다.** Gemma에서 지정 습득 청크는 1 → 1위지만 획득 청크는 2 → 5위 밖이다. KURE의 획득 청크는 3 → 5위, OpenAI에서는 습득·획득이 5·1 → 2·3위다. 지정 앵커의 변화이며 생성 답변 성능의 확정 회귀나 개선은 아니다.
- **D07은 두 포켓몬 근거를 함께 봐야 한다.** Gemma의 식스테일 등장 청크는 4 → 2위, OpenAI의 가디 등장 청크는 3 → 2위다. B에서 세 모델 모두 두 지정 앵커가 2위 이내다.
- **D01은 다른 근거가 존재한다.** Gemma의 지정 타입 청크는 A·B 모두 5위 밖이지만 반환된 다른 청크에서 타입 정보를 확인했다. 지정 앵커 미회수를 모든 근거의 부재로 해석하지 않는다.

## 문항별 지정 근거의 실제 순위

숫자는 **A → B**, `–`는 상위 5개에 없음을 뜻한다(6위 이하 순위는 모름). 같은 셀의 순서는 왼쪽의 청크 순서와 같다. 지정 청크는 유일한 정답 근거가 아니라 기존 A에서 선택한 잠정 매핑이다. 경로 기준은 `pokedex_v3a/`이며 [A 보고서](../vector-dev-10-v1/report.md)에 원문 행이 정리돼 있다.

| qid·질문 요지 | 지정 청크 (순서 고정) | Gemma A → B | KURE A → B | OpenAI A → B |
|---|---|---|---|---|
| D01 후딘 타입·종족치 | `pokemon:65#profile`, `pokemon:65#stats` | – → –, 1 → 1 | 2 → 3, 1 → 1 | 2 → 3, 1 → 1 |
| D02 식스테일 레벨업 | `pokemon:37#learnset_level` | 1 → 1 | 1 → 1 | 1 → 1 |
| D03 이브이 분기 진화 | `pokemon:133#evolution` | 3 → 2 | 1 → 1 | 1 → 1 |
| D04 캐이시 게임코너 | `pokemon:63#encounter` | 1 → 1 | 1 → 1 | 1 → 1 |
| D05 피카츄 TM24 습득·획득 | `pokemon:25#learnset_machine`, `pokemon:25#machine_acquisition` | 1 → 1, 2 → – | 1 → 2, 3 → 5 | 5 → 2, 1 → 3 |
| D06 갸라도스 방어 상성 | `pokemon:130#defense_matchup` | 1 → 1 | 1 → 1 | 1 → 1 |
| D07 7번도로 가디·식스테일 | `pokemon:58#encounter`, `pokemon:37#encounter` | 1 → 1, 4 → 2 | 2 → 2, 1 → 1 | 3 → 2, 1 → 1 |
| D08 리자몽 자속 보정 | `pokemon:6#stab` | 1 → 1 | 1 → 1 | 1 → 1 |

### 원문을 다시 확인한 사후 대체 근거 — 점수에는 반영하지 않음

- D01 Gemma B의 4위 `pokemon:65#defense_matchup`에는 후딘 에스퍼 타입을 언급한 [후딘 문서 132행](../../pokedex_v3a/documents/065_후딘.md)이 있고, 1위 `pokemon:65#stats`에는 스피드 120·특수 135가 16행에 있다. A에서는 같은 방어 상성 청크가 2위, 자속 청크가 5위(116행)다. 청크 본문과 원문 행을 재확인한 탐색적 대체 근거이지 사람의 최종 적합성 채점은 아니다.
- D03 Gemma B 1위 `pokemon:134#evolution`과 3위 `pokemon:136#evolution`은 각각 [샤미드 문서 23·25행](../../pokedex_v3a/documents/134_샤미드.md), [부스터 문서 23·25행](../../pokedex_v3a/documents/136_부스터.md)에 두 갈래 진화 조건을 모두 담는다. A에서는 각각 1·2위다. 지정 이브이 청크만이 유일한 답변 근거가 아니다.
- D05 Gemma B의 다섯 반환 청크를 원문 연결된 청크 본문에서 직접 살펴보면 1위 습득 청크는 TM24·10만볼트를 담지만, 나머지 네 청크는 피카츄 획득처·진화, 메타몽 머신 목록 없음, 라이츄 진화다. 확인된 다섯 본문에 TM24 장소·방법이 나타나지 않는다. 지정 획득 청크의 [피카츄 문서 90행](../../pokedex_v3a/documents/025_피카츄.md)은 그 사실을 담는다. 이는 이번 반환 후보의 범위 내 관찰이고 코퍼스 전체의 다른 대체 근거 부재나 실제 답변 오류를 확정하지 않는다.
- D07 양쪽 지정 근거는 [가디 문서 130행](../../pokedex_v3a/documents/058_가디.md)과 [식스테일 문서 128행](../../pokedex_v3a/documents/037_식스테일.md)에서 각각 Red·Blue 7번도로 레벨 18·20을 기록한다. D05의 습득·획득 역시 같은 사실이 아니라 별도 사실이다.

## 근거 없음 D09·D10: 검색 정상, 거절 미평가

D09는 코퍼스 범위 밖 리아코 종족치, D10은 현재 코퍼스 정보 부족으로 분류된 피카츄 포획률 질문이다. D10의 부재는 [제안서](../../docs/proposals/dev-vector-10-draft-20261125.md)에 적힌 표현 범위의 관찰이지 모든 표현과 자료의 부재 증명이 아니다. **A와 B 모두 각 모델에서 두 질문에 대해 정상적으로 5개 청크를 반환했다.** 검색 결과만으로 거절 성공·실패를 판정하지 않는다. 답변 생성과 거절 평가를 실행하지 않았으며 사람 채점은 `pending`이다.

| 문항 | B Gemma 1위 | B KURE 1위 | B OpenAI 1위 |
|---|---|---|---|
| D09 | `pokemon:115#evolution` | `pokemon:115#evolution` | `pokemon:113#evolution` |
| D10 | `pokemon:25#profile` | `pokemon:25#profile` | `pokemon:25#defense_matchup` |

전체 A/B top5와 문항별 순위는 [score.json](score.json), 원본 후보와 전체 융합 풀은 [raw.json](raw.json)에 있다.

## 방법과 한계

- B의 BM25는 NFKC+casefold, 한글 연속 문자열 전체와 겹치는 음절 bigram, ASCII 영숫자 연속 문자열을 사용한다. 구두점으로 분리하고 질문 토큰을 중복 제거하며 조사 제거 사전은 없다. `k1=1.2`, `b=0.75`; 겹침이 없으면 빈 결과. 한국어 형태소 분석기와 같지 않다.
- BM25 최대 20개와 모델별 exact cosine Vector 최대 20개를 가중치 1:1, `sum(1/(60+rank))`로 융합하고 ID 기준 중복 제거·동점 ID 오름차순 후 최종 5개를 반환한다. 융합 풀은 24–39개. A는 Vector top5다. C 재정렬은 실행하지 않았다.
- 동일 원문 질문·청크 및 기존 DB/인덱스 사용은 실행 전 기록과 해시가 뒷받침한다. 이번 독립 평가는 고정 원본을 오프라인으로 읽은 것이므로 당시 DB 상태·실행 설정 전체를 독립 재검증하지 못했다. 기록된 인덱스 및 설정 해시 불일치는 발견되지 않았으나 전체 유효성 확정은 불가하다. 질의 벡터는 별도로 새로 생성됐고 top5 ID 순서만 일치한다.
- OpenAI 모델은 불변 리비전이 아닌 별칭이다. 임의 모델에서 임베딩 벡터의 비트 동일성을 보장하지 않는다. 실제 청구 비용은 `unknown`, 시간은 통제된 성능 측정이 아니다. 팀 공유 재현은 과거 DB identity preflight가 로컬 scratch에만 있어 현재 결과 폴더만으로는 불가능하다. 실행 재현에는 별도 환경·모델·자격 증명·DB와 승인, 추가 비용이 필요할 수 있다.
- 표본은 답변 가능 8개뿐이고 기존 A에서 사용된 선정 앵커는 공식 허용 근거로 승인된 것이 아니다. 사람의 정답 충족·근거 적합성·거절 판단, 답변 생성 및 정식 평가가 남아 있다. 이 수치만으로 모델·방식 채택이나 무조건적 우열을 결론 내리지 않는다.
- B 배치 사용량 기록은 Gemma `prompt_eval_count=302`, KURE `prompt_eval_count=304`, OpenAI `prompt_tokens=516`, `total_tokens=516`이다. 모델별 토크나이저가 달라 숫자를 직접 비교하지 않는다.
