# BM25 + 벡터 RRF 개발 검색 원본

이 폴더는 정식 평가나 답변 생성이 아닌 **검색 전용 개발 스모크 실험**이다. 질문 10개를 Gemma·KURE·OpenAI 각각에서 검색했다. 원본 고정 후 독립 평가자가 기존 A의 잠정 지정 근거를 사용해 검색 회수 점수를 계산했다. 이는 사람의 답변·근거·거절 채점이 아니며 정식 평가셋의 확정 허용 근거도 아니다.

## 고정 조건

- 동일 공통 청크 1,504개, `pokedex_v3a_full_v1`, `v3a_full_151_20261125_v1`. 벡터는 모델별 기존 테이블, 버전 조건 외 의미 필터 없음. 문서 재임베딩 없음.
- BM25는 한 번 만든 인덱스를 공유한다. NFKC+casefold 후 한글 연속 문자열 전체와 겹치는 한글 음절 bigram, ASCII 영숫자 연속 문자열을 토큰으로 사용한다. 구두점은 분리하고 질문 토큰은 중복 제거한다. 조사 제거 사전을 사용하지 않는다. `k1=1.2`, `b=0.75`, IDF `log(1+(N-df+0.5)/(df+0.5))`; 겹치는 토큰이 없으면 빈 목록이다. 최대 20개.
- 모델별 exact cosine 순차 스캔 최대 20개와 BM25 최대 20개를 가중치 1:1의 `1/(60+rank)` RRF로 합친다. 동점은 `chunk_id` 오름차순, 최종 5개. 서로 다른 원점수를 합산하지 않는다. 향후 C의 재정렬 입력이 될 B의 전체 합집합을 `fused_candidates`에 보존하며 C는 실행하지 않았다.
- 세 모델에 같은 질문 원문을 한 번씩 배치로 전달했다. 클라이언트 접두사는 없고 로컬 모델에 `truncate=false`, `num_ctx=8192`를 전달했다. 서버 내부 전처리·토큰화의 완전한 동일성은 보장하지 않는다. OpenAI 모델 식별자는 불변 리비전이 아닌 별칭이다.

## 파일

- `questions.json`: 기존 A의 질문 전용 바이트 사본. SHA-256 `d926f26b383b0f7ed2ea540a3a365895461ccc8619e4fbf7a2017e79b36813e1`.
- `config.json`: 실행기가 실제로 대조한 설정. SHA-256 `f663cc0cdfacc5a53c01c309eca894bf96d8f414c02e1b6e89edf73751c09854`.
- `raw.json`: 30개 모델×질문별 BM25와 벡터 후보, RRF 전체 풀과 최종 5개, 출처 메타데이터, 상태 및 측정 시간. SHA-256 `7ef2d1d6de7e7e0ff0d74941eafc6039b6ab7d4593d0ba000ab857eb7e5fa509`.
- `execution-started.json`: 실요청 전에 배타 생성된 표식. `run.py`는 기존 표식이나 원본이 있으면 재실행하지 않는다. 각 배치 요청 직전 원본의 상태를 `request_outcome_unknown`으로 기록하며 자동 재시도하지 않는다.
- `run.py`, `test_run.py`, `verify.py`, `checks.json`: 실행기, 오프라인 테스트, 무채점 구조 검증기와 검증 기록. `verify.py`는 `checks.json`을 배타 생성하므로 기존 파일이 있으면 덮어쓰지 않는다.
- `report.md`, `score.json`: 독립 평가자의 잠정 지정 근거 검색 회수 A/B 비교 보고서와 기계 집계. 사람 채점은 대기 중이다. 과거 A 원본 `../vector-dev-10-v1/raw.json`의 SHA-256은 `9a76848d3e757ac2ba1565ed54ebe205303bbe9fdcd11389237fb911a5e9f2b8`이며 수정하지 않았다.
- `score_offline.py`, `test_score_offline.py`: 원본을 읽기만 하는 독립 계산·검증 스크립트와 오프라인 테스트. 재검증은 `python results/hybrid-dev-10-v1/score_offline.py --check`.

## 실행 및 검증 범위

사전 오프라인 단위 테스트 8개 통과 후 실제 DB를 `REPEATABLE READ READ ONLY` 및 기존 NOLOGIN 실행 역할로 연결했다. 과거 preflight 기록 해시와 DB·역할·스키마·인덱스 설정, 각 모델의 1,504개 ID·본문 해시 대응·차원·벡터 집합 다이제스트, 로컬 모델 digest를 확인했다. BM25 코퍼스는 같은 트랜잭션에서 읽은 청크 본문과 해시를 검증해 구성했다. 각 검색 SQL의 EXPLAIN에서 순차 스캔 및 인덱스/bitmap 비활성화를 확인했다. 읽기 전용 역할 전환은 관리자 로그인에 대한 보안 샌드박스가 아니다.

기존 A 실행 코드의 해시 고정 도우미를 재사용한다. DB identity의 과거 사전 기록은 로컬 scratch에만 있으므로 이 결과는 다른 환경에서 그대로 재실행 가능한 독립 패키지가 아니다. 동일 실행을 다시 하면 세 모델에 새 요청과 비용이 발생할 수 있으므로 별도 승인 없이는 재실행하지 않는다. 원본 벡터와 자격 증명은 저장하지 않는다. 측정 시간은 통제된 성능 벤치마크가 아니다.
