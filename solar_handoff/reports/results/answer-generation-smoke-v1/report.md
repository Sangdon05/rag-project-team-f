# 답변 생성 소량 실제 시험: 독립 근거 대조 보고서

**상태: `scoring_pending` — 사람 채점 전.** 이 문서는 답변과 제공 근거의 관찰 기록이지 점수나 모델 채택 판정이 아니다. 실제 생성 결과는 12건 모두 `ok`이며 실행은 완료됐다. 아래 차이는 각 조건에서 한 번씩 나온 결과다. 공식 평가 점수, 전체 우열, 반복 안정성 또는 운영 성능을 뜻하지 않는다.

## 무엇을 비교했나

- 개발용 **비공식 제안** 중 3문항: D05는 두 사실을 연결해 답변 가능한 질문, D09는 범위 밖, D10은 코퍼스에 포획률 정보가 부족한 질문이다. [제안서](../../docs/proposals/dev-vector-10-draft-20261125.md)는 정답·허용 근거가 확정된 평가셋이 아니다.
- 검색 단계는 기존 결과를 재사용했다. **A는 Vector**, **B는 BM25+Vector**이고, 이 보고서의 검색 임베딩은 3개 임베딩 모델 전체가 아니라 **Gemma의 A/B만**이다. 답변 모델은 그와 별개인 **GPT-6 Luna**와 로컬 **EXAONE 3.5 7.8B 양자화 모델** 두 가지다. 임베딩 3모델 비교 결과를 답변 모델 2개 비교로 혼동하면 안 된다.
- 질문 3개 × 검색 방식 2개 = **6개 저장된 입력 case**. 각 case마다 두 답변 모델이 **각각 1회** 생성해 12건이다. 같은 case의 질문, 순서가 있는 청크 5개 및 시스템 지침은 동일하다. A와 B 사이에는 검색된 청크 또는 순서가 다르며 모델별 API와 파라미터도 다르다. 눈가림 시험이 아니다. 실시간 검색·툴 선택을 포함한 전체 에이전트 시험도 아니다.
- D05 원문은 [피카츄 문서](../../pokedex_v3a/documents/025_피카츄.md) 59행에 TM24·10만볼트, 90행에 갈색체육관·NPC 보상으로 기록한다. 두 사실을 각각 확인해야 한다. D09의 범위 밖 분류와 D10의 정보 부족 분류는 제안서 기준이다. D10의 표기 검색 관찰은 다른 표현·다른 자료에 수치가 없다는 뜻이 아니다.

### 읽을 때 주의할 차이

1. **D05의 A/B 차이는 입력 정보 차이와 함께 봐야 한다.** 두 모델 모두 A에서는 머신과 갈색체육관 NPC 보상을 말했고, B에서는 TM24를 말하되 장소·방법을 확인하지 못한다고 답했다. B의 5개에는 지정 획득 청크뿐 아니라 이를 대신 뒷받침하는 장소·방법도 보이지 않는다. 관찰된 차이를 단일 시행에서 검색 방식 또는 모델 능력의 일반적 인과 효과로 단정하지 않는다. A EXAONE은 획득 청크만 인용하므로 머신-기술 연결에 대한 인용 적합성은 사람이 별도 검토해야 한다.
2. **B D09 EXAONE의 부가 주장은 제공 근거와 다르다.** “리아코에 대한 진화 정보는 있지만”이라는 말은 5개 청크에 의해 뒷받침되지 않는다. `pokemon:114#evolution`은 리아코가 아니라 덩쿠리의 진화 설명이며, 답변 후반의 다른 포켓몬 설명과도 긴장된다. 종족치 수치를 제시하지 않은 사실과 별개로 살펴볼 문제다. A D09의 `[[chunk_id]]`는 설명 중 형식 예시처럼 사용됐더라도 실제 제공 ID가 아니어서 자동 검출상 무효다.
3. **D10에서 인용 ID가 유효해도 포획률 사실 검증은 되지 않는다.** `pokemon:25#encounter`는 장소·방법·레벨을 제공할 뿐 수치가 없다. 이 청크는 B EXAONE의 장소·레벨에 관한 부연을 뒷받침하지만, 그 하나만으로 나머지 청크나 전체 코퍼스에 수치가 없음을 증명하지 못한다. 이 경우 결론은 다섯 본문을 각각 확인한 범위의 부재다. 포획률이 게임에 없거나 다른 자료에도 없다는 주장이 아니다.
4. 기록기의 `citations=[]`와 `invalid_citations=[]`는 각각 검출된 인용 없음과 검출된 무효 ID 없음을 뜻한다. 특히 A D09 EXAONE은 `citations=["chunk_id"]`, `invalid_citations=["chunk_id"]`, `no_citations=false`다. 인용이 없는 근거 부족 답변은 반드시 오류가 아니고, 반대로 유효 ID만 있다고 주장이 참이라는 뜻도 아니다. 자동 검사는 이중 대괄호 형식의 ID 존재만 살피며 의미적 근거 적합이나 다른 형식 출처의 환각을 판정하지 않는다.

## 실행 조건과 재현 한계

- 원본 `run_started`: 요청 모델 `gpt-6-luna`와 `exaone3.5:7.8b-instruct-q4_K_M`; 결과의 실제 모델 값도 각각 일치. GPT는 `reasoning.effort=low`, `max_output_tokens=1024`, `store=false`, `stream=false`이고 **temperature는 전송 설정에 없음**. EXAONE은 `temperature=0`, `num_predict=1024`, `num_ctx=8192`, `stream=false`. 동일한 설정이라고 말할 수 없다.
- EXAONE 사전 확인 및 각 로컬 결과 전후의 digest는 `c7c4e3d1ca22fe9225f18b35eb719f67e2ca96a42e7fd17294a45b83ba8fbf03`. 전후 일치는 그 사이 교체 가능성을 원자적으로 배제하지 않는다. GPT alias의 불변 revision/digest는 기록되지 않아 **unknown**이다.
- 위 토큰은 GPT의 `input_tokens`/`output_tokens`, EXAONE의 `prompt_eval_count`/`eval_count`다. 토크나이저가 다르므로 토큰 수를 같은 단위의 비용이나 효율로 직접 비교할 수 없다. 비용은 측정되지 않아 unknown이다. 지연은 한 번의 호출이며 로컬 digest 조회는 제외된다. 부하·호출 순서·네트워크·하드웨어 차이를 통제한 벤치마크가 아니다. 두 모델의 출력 한도는 각각 1024로 설정됐으나 토큰 단위가 동일하다는 뜻은 아니다.
- 온도 0도 결정성을 보장하지 않는다. 문항·방법·모델별 한 번의 생성만 관측했으므로 반복 변동과 일반화 가능성은 미확인이다. 사람이 원본 문장과 근거를 보고 정확성·완전성·인용 적합성·근거 부족 대응을 독립적으로 채점해야 한다. 공식 점수나 전반적 우열은 제시하지 않는다.
