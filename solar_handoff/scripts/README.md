# 오프라인 문서·청크 생성

영문 Red·Blue 기준이다. Python 3.13 이상과 표준 라이브러리만 사용하며, DB·API·모델·환경 변수·기존 테스트나 승인 시스템이 필요하지 않다. 경로는 스크립트 위치를 기준으로 해석한다.

- `../data/processed/`: 정제 JSON 11개. `../data/source_manifest.json`: 출처 기록. `../data/document_register.json`: 문서 및 근거 경로·상태.
- `../documents/`, `../document_evidence/`: 각각 151개. 001·002는 역사적 특수 문서와 근거이며 재생성하지 않고 그대로 복사한다. 003–151은 입력으로 생성한다.
- `../chunks/draft-a-v1/chunks.jsonl`: 1,504개 제목 단위 A안 청크. `manifest.json`은 당시 기록이며 아래 새 생성기의 입력이 아니다.

아래 명령은 저장소 루트에서 실행한다. 쓰기 모드의 출력은 반드시 기존 입력 폴더와 겹치지 않는 **새 경로**여야 하며 부모 디렉터리는 존재해야 한다. 기존 경로는 덮어쓰지 않는다. 실행 중 실패하면 일부 출력 디렉터리가 남을 수 있으므로 직접 확인해야 한다. 동시 변경은 지원하지 않는다.

```sh
python -B solar_handoff/scripts/build_v3a_documents.py --check
python -B solar_handoff/scripts/build_draft_chunks.py --check
python -B solar_handoff/scripts/build_v3a_documents.py --output /별도/새_문서_폴더
python -B /별도/새_문서_폴더/scripts/build_draft_chunks.py --output /별도/새_chunks.jsonl
```

`--check`는 기존 문서 003–151과 근거의 레코드 연결·계산, 기존 청크 1,504개의 재생성을 대조한다. 새 문서 폴더는 정제 입력·출처 목록·생성 코드를 함께 포함한다. 원본 보존이 우선이므로 기존 문서·근거·청크는 변경하지 않는다. 새로 만든 003–151 근거는 현재 코드와 입력의 출처 정보로 기록되므로 역사적 근거 파일과 바이트가 다르고, 이를 반영한 새 청크의 근거 해시도 달라진다. 문서 내용·청크 ID·본문·근거 연결은 재현된다. 이후 별도로 인덱스를 갱신하고 평가해야 한다.

기존 근거와 청크 manifest 안의 과거 스냅샷 경로·코드 해시·revision은 당시 이력을 나타낸다. 해당 스냅샷 파일이나 테스트는 여기 포함되지 않으며, 현재 코드에 대한 검증값으로 해석하면 안 된다. Git의 줄바꿈 변환은 원본 바이트와 청크의 문서 해시 연결을 바꿀 수 있으므로 전달 시 파일 바이트가 보존되는지 별도로 확인한다.

자료는 초안 상태(`pending`, `index_eligible=false`)로 보존한다. 생성과 기계적 대조는 사람의 사실 검토나 운영 승인이 아니다. 근거 연결은 절·의존성 단위이고 행별 사실 검증은 아니다. 001의 과거 획득 레벨 집계는 기록되지 않은 중간 레벨을 암시할 수 있다. 외부 원본의 완전한 재수집·사실 완전성과 재배포 권리는 별도 확인이 필요하다.
